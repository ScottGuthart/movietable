# Handoff

Open items that need the Apple Developer account or a dashboard login. Delete each once done.

- [ ] Add repository secrets `SUPABASE_URL` and `SUPABASE_ANON_KEY` (GitHub → movietable → Settings → Secrets and variables → Actions → New repository secret). Until then, Apple CI builds with `https://api.movietable.ai` and a placeholder key; the app's data and sign-in features will not reach Supabase from CI builds.
- [ ] Attach `apple/MovieTable/MovieTable.entitlements` in Xcode (project MovieTable → target MovieTable → Signing & Capabilities → + Capability → Associated Domains and Sign In with Apple; drag the entitlements file in or re-add the two capabilities so Xcode writes `CODE_SIGN_ENTITLEMENTS`). The file already carries `applinks:movietable.ai` and Sign in with Apple.
- [ ] Apple Developer Program: enable Sign in with Apple on the App ID (developer.apple.com → Certificates, Identifiers & Profiles → Identifiers → movietable.ai.MovieTable → Capabilities → Sign in with Apple → Save). Then replace `TEAMID` with the team ID in `public/.well-known/apple-app-site-association` (two occurrences) and deploy the website so https://movietable.ai/.well-known/apple-app-site-association serves it.
- [ ] Supabase dashboard: Authentication → Providers → Apple → enable, paste the Services ID `movietable.ai.MovieTable` and the secret key from the Apple key, and save. Authentication → URL Configuration → add `https://movietable.ai/auth/callback` to the redirect allow-list for magic links.
- [ ] Google iOS client ID: create an iOS OAuth client (Google Cloud console → APIs & Services → Credentials), add the GoogleSignIn-iOS package to `apple/Packages/MovieTableData`, put the client ID in `apple/Config.xcconfig` as `GOOGLE_CLIENT_ID`, register its URL scheme in Info.plist, and wire `GIDSignIn` so the Google button calls `account.signInWithGoogle(idToken:)`. `AuthController.signInWithGoogle` is ready; only the SDK token step is missing.
